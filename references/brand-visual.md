# 品牌视觉与文案调性

这份文档管两件事：卡片长什么样，以及卡片上每句话怎么说。

> **v1.2 起，卡片由 `scripts/render_card.py` 确定性渲染，本文件是那个渲染器的规格说明。**
> 正常流程不用读它 —— 模型手写一份卡片要几分钟，且每次都不一样。
> 只有要改卡片结构/配色/文案模板时才翻，改完同步改渲染器，并跑 `tests/test_render.py`。

**前提：作品要提交给麦当劳赞助的比赛，品牌调性优先于宿主主题。** 不要把卡片做成"跟随 IDE 深浅色"的中性组件 —— 它应该一眼看出来是麦当劳出的东西。

---

## 一、为什么不能跟随主题

跟随宿主主题会带来两个具体问题：

1. **深浅色各出一版，视觉不一致。** 评委在不同机器上看到的是两张不同的卡，品牌识别被打散。
2. **主题变量拿不到品牌色。** `--color-text-primary` 之类的语义变量在深色主题下是白字，压在金底上直接不可读。

所以：**卡片自己铺不透明底色，所有颜色写死 hex，不引用任何主题变量。** 深色宿主下它是一块浅色卡，这是有意为之，不是 bug。

## 二、设计令牌（Design Tokens）

### 主色（必须用这几支，改色即报错）

| 角色 | Hex | 用在哪 | 配额 |
|---|---|---|---|
| 麦当劳红 | `#DA291C` | L1 标题底色、实付金额、超阈值、依据标签 | ≤ 15% |
| 金拱门黄 | `#FFBC0D` | 角标（最省/蛋白最高）、排序标记、金拱门徽章 | ≤ 10%，**不铺大块** |
| 暖奶油 | `#FFF8E7` | 卡片内容底衬、营养胶囊底 | 大面积 |
| 深炭黑 | `#27251F` | 正文（奶油底上 WCAG AAA） | 大面积，要留白 |
| 中灰 | `#8C857B` | 次级字、划线原价、口径说明 | 小面积 |
| 省钱绿 | `#1B873F` | 只在「立省 ¥X」绿标上出现 | 极小 |
| 分隔线 | `#EFE4CD` | 1px 边框、行分隔 | 线状 |
| 页面底 | `#F2E9D8` | 卡片外的页面底色，比奶油深一档让卡片浮起来 | 大面 |

**只用红/金 + 中性 + 一支绿。** 不要引入蓝紫。区分方案用金色深浅，不换色相。
绿色是例外且只有一处用途：省钱金额。别拿它做「健康/达标」的暗示。

### 圆角系统

| 层级 | 值 | 用在哪 |
|---|---|---|
| 外层容器 | `18px` | 每套方案的卡 |
| 内层模块 | `12px` | 餐品行、营养看板 |
| 胶囊/角标 | `999px` | 千卡/蛋白胶囊、状态角标 |

### 字体与字号

用户系统字号已放大，宁可变宽，不许缩字。

| 层级 | 字号 | 字重 | 备注 |
|---|---|---|---|
| L1 方案名 | 26px | 700 | 「主品名」+ 基调 + 套 |
| 页面标题 | 24px | 700 | 这顿怎么点 |
| 餐品名 | 19px | 400 | 单行截断 + `title` |
| 营养数字 | 21px | 600 | 等宽对齐 |
| 实付金额 | 42px | 700 | 等宽、`letter-spacing:-1px` |
| 依据正文 | 17px | 400 | 行高 1.75 |
| 标注（胶囊、口径） | 16px | 400 | **不低于 16px** |

- 数字一律等宽：`font-variant-numeric: tabular-nums;`
- 价格两位小数：`¥14.90`，不是 `¥14.9`
- 千卡写 `kcal`，蛋白 `29g`，钠取整 `1018mg`
- 不用 emoji。金拱门用 SVG 矢量两拱，不用图片、不用字形拼
- 允许极轻阴影 `0 2px 10px rgba(39,37,31,.07)`；**不用渐变、发光**

## 三、五层视觉动线

每套方案一张卡，**单卡最大宽度 432px**，容器 `flex-wrap` + `flex:1 1 392px`：
宽屏两列并排横着比，窄屏（<860px）自动折成上下流式。

| 层 | 内容 | 硬要求 |
|---|---|---|
| L1 | 红底标题：`方案 A` + 角标 + **具象方案名** | 名字来自主品，不是「方案A」当标题 |
| L2 | 餐品清单：**套餐拆成单品逐行**，分类图标 + 来源前缀 + 单行菜名 + 份数 + 千卡胶囊 | 一行一件；查不到营养写「未收录」，不写 0 |
| L2' | 差异化配餐分三组，组头带 `轻食 1 人 / 每人 369 kcal`、`照常 2 人 / 每人 614 kcal`、`共享 大家分` | 每份都要看得出归谁 |
| L3 | 价格看板：实付最大 + 立省绿标 + 划线原价 + 人均 | 数字来自 `calculate-price` |
| L3' | 营养看板：合计 kcal / 蛋白 / 钠，超限标红 | 一眼能判超标 |
| L3'' | 三条依据：算账 / 营养 / 口味或搭配 | 每条都指得出具体数字 |

**方案名写法**：`「主品简称」+ 口感或营养基调 + 套`
例：`「双层吉士」高蛋白暴击套` / `「双层吉士」甜口收尾套`。
依据只能从这套的事实里取（蛋白/元最高、热量最低、含甜点），**不许编口感**。

**至少两套**：只给一套等于没得选。约束太紧时脚本会先松营养上限、再松预算补第二套，
补出来的那套在 `warnings` 里注明「是放宽后的备选」，卡片上靠「超预算」角标照样看得见。

## 四、三大兜底（都不许退化成白块）

1. **图标** → 用 `scripts/mcd_icons.py` 的 21 类自绘 SVG，**不用菜单接口的产品图**。
   官方图是 427×320 的促销横幅（带「随心配1+1」「100%纯牛肉」角标、粉蓝撞色底），
   缩到 34px 只剩色块和字，比没图更糟；外链还可能被宿主容器拦掉。
   认不出类别时上**红底金拱门**（simple-icons 的 mcdonalds 路径），不画问号、不硬套汉堡。
2. **长菜名** → `white-space:nowrap; overflow:hidden; text-overflow:ellipsis` + `title` 浮窗。
   名字被截断是设计内的，撑破行不是。
3. **窄屏** → 卡片 `min-width:0`（flex 子项默认 `min-width:auto` 会把卡顶出屏幕），
   营养看板格子 `flex:1 1 0`，胶囊竖排。375px 下不许出现横向溢出。
4. **套餐拆平** → 卡片上不出现「人气经典随心配」这类 SKU 名，按子项一行一件。
   份数全清单一致时靠标题「人手一份 ×3」交代，行内不再挂；单品营养缺就写「未收录」，
   绝不用套餐合计均摊——那是编数。
5. **来源前缀** → 拆平后套餐名消失了，每件单品前挂 14px 灰字前缀
   「随心配-双层吉士汉堡」。前缀取套餐名里的品类词（随心配 / N 件套 / 1+1），
   没有就取前 3 字；单点**不加**前缀。拆平不留归属，折扣那笔账就对不上。
6. **规格推定** → 菜单没写规格、营养表按中份对上的（薯条 ← 中薯条），
   热量胶囊前面加 `≈`。这是推定不是命中，不能装成精确值。
7. **0 卡** → 纯悦、冰水这类真 0 卡，必须显示「0 kcal」，不能因为 0 是 falsy
   就打成「未收录」。**「未收录」只留给真的查不到**。
8. **差异化配餐** → 组头写人数和每人热量（`轻食 1 人 / 每人 369 kcal`），
   底部营养看板改说「轻食那位 369 kcal」。这时候「人均 629 kcal」是误导：
   控卡的人会以为自己也吃了 629，实际他 369。

## 五、文案调性：麦门老友

不是客服口吻，也不是广告口吻。是**一个常来的熟客帮你点单**：知道东西多少钱、知道哪个值、不忽悠。

### 三条硬规则

1. **先给数字，再给评价。** 评价是数字的结论，不是替代品。
2. **能给实数的绝不给形容词。** "省 8.6 元" > "超值"。
3. **不打包票。** 不说健康功效、不说"吃不胖"、不承诺减脂。

### 禁用词表

`零负担` `无负担` `吃不胖` `健康之选` `营养均衡` `经典搭配` `不容错过` `家人们` `绝绝子` `YYDS` `超值优惠` `暖心推荐` `低卡轻食` `健康无负担`

出现任何一个，这句话重写。代码里 `BANNED` 会自动拦，`--strict` 下直接非 0 退出。

### 正反例

| ❌ 不要写 | ✅ 应该写 |
|---|---|
| 这套搭配营养均衡，健康无负担 | 482 kcal，钠 1018mg，占日上限一半出头 |
| 超值套餐，不容错过！ | ¥14.90，比单点这两件便宜 8.6 元 |
| 精选优质蛋白，助力你的健身计划 | 蛋白 29g，每元换到 1.95g，这价位里最高 |
| 为你精心搭配的黄金组合 | 主品双层吉士，咸香对得上，配中薯、可乐 |
| 低卡轻食，吃了也不怕胖 | 429 kcal，比你给的 700 留了 271 的余量 |

### 三条依据的写法模板

每条都要能追溯到**具体约束**或**具体商品**，写不出就不写。

**【算账铁证】** 金额必须来自 `calculate-price` 或菜单价差，注明口径。

> 实付 ¥44.70，菜单划线价 ¥52.50，结构省 ¥13.00（套餐自带折价，不是券）

**【营养铁证】** 数字必须来自营养表累加，标出占用户上限的比例。

> 1287 kcal，占 2100 上限的 61%，蛋白 81g，钠 3051mg，人均 429 kcal

**【口味与场景铁证】** 把用户偏好原话接进来；对不上就老实说对不上。

> 这套里没有辣味，是照每元蛋白排的先后

**不许代述用户原话。** 卡片上不出现「你说想吃 X」「为你挑的」这类第一人称陈述：
`--prefer` 的值可能来自脚本默认值或测试命令，来源不可追溯，写成「你说」就是替他发言。
口味这条只描述**这套里有什么、对不对得上**。真要引原话，必须带引号且逐字引用，
并只由对话原文传入。

### 排序理由（标题下一行）

多方案并排时，必须说清凭什么这么排，而不是只给"方案 A/B"。

```
排这一位，因为实付最低、热量最低
换它的代价：比方案 A 贵 15.00 元，热量多 279 kcal，蛋白多 6g
```

## 六、出卡前自查

- [ ] 奶油 `#FFF8E7` 打底、卡面纯白、没有引用任何主题变量
- [ ] 红色只在标题栏/实付/标签，金色没铺成大块，绿色只用在「立省」
- [ ] 外层圆角 18px、内层 12px，没有出现 4px 小圆角
- [ ] 价格两位小数且等宽；kcal / g / mg 单位齐全
- [ ] 套餐写了拆解子项，单点写了角色（主品/配品/饮品）
- [ ] 外送写了运费、打包，别让「实付」口径含糊
- [ ] 每套有一句排序理由，且说的是可比数字
- [ ] 三条依据各自指得出具体商品或具体约束
- [ ] 图文兜底在：`onerror` 徽章、`text-overflow:ellipsis` + `title`
- [ ] **至少两套方案，单卡 ≤432px，宽屏两列、窄屏折叠**
- [ ] 全文搜一遍禁用词表，零命中；无 emoji
- [ ] 标题 ≥24px、正文 ≥18px、标注 ≥16px、行高 ≥1.75
