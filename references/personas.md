# 人群画像与参数映射

画像的用途只有一个：**把用户的模糊需求翻译成 `mcd_planner.py` 的参数**。不做画像也能点餐，但会退化成"随机推个套餐"。

## 一、四维打分（用于多个画像都沾边时定夺）

| 维度 | 分值 | 判据 |
|---|---|---|
| 时段 | 30 | 早 06:00-10:29 / 午 11:00-13:30 / 下午茶 14:00-17:30 / 晚 17:30-21:00 / 夜宵 21:00+ |
| 人数与社交 | 25 | 1 人 / 2 人 / 3-4 人 / 5 人+ |
| 预算与羊毛 | 25 | 有明确预算数字 / 提了"便宜""优惠券" / 无预算概念 |
| 饮食目标 | 20 | 提了热量、蛋白、控卡、低钠、忌口、健身 |

**高置信度**：最高分 ≥ 70 且领先第二名 > 5 → 出 1 主推 + 1 备选
**低置信度**：最高分 < 70 或前两名差 ≤ 5 → 前两名各出一套，并排给

## 二、六个画像 → CLI 参数

### P1 上班族·工作日极速充能
> 触发：工作日午间、一个人、说"快点""随便吃点"

```bash
--kcal-min 500 --kcal-max 900 --protein-min 25 --objective value --structure with_drink
```
主指标：蛋白与碳水双达标 + 不需要两只手（避开需要剥壳/大块撕咬的）。有咖啡就带咖啡。

### P2 自律党·轻盈高蛋白控卡
> 触发：提了热量数字、蛋白、减脂、健身、"别超过 xxx 卡"

```bash
--kcal-max <用户给的值> --protein-min 30 --sodium-max 1200 --objective value --structure with_drink
```
主指标：`protein / price` 最大化，钠和脂肪做惩罚项。
**这是最容易出错的一档**：必须保证套餐拆解完整，否则热量偏低、方案看着合规实际超标。

### P3 学生与青年·下午茶/夜宵摸鱼
> 触发：14:00-17:30 或 21:00 后、"来点甜的""想吃小食"

```bash
--objective budget --structure full --top-k 3
```
主指标：券后立省最大化 + 甜咸搭配。这一档允许营养不完美，别拿控卡标准去劝人。

### P4 家庭与老友·周末欢聚
> 触发：2-4 人、周末、说"一起吃""带小孩"

```bash
--people <人数> --budget <总预算> --objective budget --exclude 辣 --top-k 2
```
主指标：桶餐/分享盒的结构省 + 不辣儿童友好单品。**主动排掉带"辣"的单品**，除非用户说能吃辣。
多人自动跑两条路径：「分享装 + 饮品×N」（桶类结构省大）和「人手一份 ×N」，并排给用户选。

### P5 早八人·通勤元气唤醒
> 触发：06:00-10:29、说"早餐"

```bash
--reservation "<当天日期> 08:00" --kcal-max 600 --objective value --structure with_drink
```
**必须传 `reservationDate`**，否则查出来的是当前时段的菜单，早餐品类全部缺失（见 `mcp-contract.md` 第 5 条）。

### P6 团队与黑客松·多人团餐
> 触发：5 人+、会议、比赛、公司订餐

```bash
--people <人数> --be-type 6 --order-type 2 --budget <总预算>
```
团餐走 `beType=6`，需要先 `query-meal-assistance` 拿 `gmServiceCode`，再用 `query-promotions` 看满减阶梯。
**本 skill 的求解器只负责挑单品组合，不算 300/500 阶梯折上折** —— 阶梯优惠要在核价后单独叠加，别把两笔钱混在一起报。

## 三、口味与饮食偏好 → 参数映射

**这一节是赛题输入项，不是可选项。** 口味和饮食偏好必须问，问完必须落到 CLI 参数上，不能问完就搁着。

### 3.1 口味偏好 → 排除/包含

| 用户选的 | CLI | 说明 |
|---|---|---|
| 想吃辣 | `--include 辣` | 主动往辣味单品靠（麦辣鸡腿堡、麦辣鸡翅、蘸酱炸鸡） |
| 清淡不辣 | `--exclude 辣` | 排掉带"辣"的单品。**儿童、长辈、胃不好的一律按这档** |
| 甜口 | `--include 新地 麦旋风 派` | 允许甜品占一个配品位，热量上限要留出余量 |
| 咸香厚重 | `--include 双层 巨无霸 安格斯` | 偏牛肉、偏芝士 |
| 都行 | 不加参数 | 交给求解器按 `--objective` 排序 |

### 3.2 饮食偏好 → 约束与排序

| 用户选的 | CLI | 排序指标 |
|---|---|---|
| 控卡减脂 | `--kcal-max <值或800> --sodium-max 1500 --objective value` | 蛋白/元优先，热量硬卡 |
| 高蛋白增肌 | `--protein-min 30 --kcal-min 500 --objective value` | 蛋白绝对值与效率双看 |
| 低钠清淡 | `--sodium-max 1000 --objective sodium` | 钠最低 |
| 无特殊要求 | 不加约束 | `--objective budget` 或 `value` |
| 有忌口 | `--exclude <忌口词>` | 牛/鸡/鱼/猪/乳/麸质/花生，按词排 |

**冲突处理**：用户既要"高蛋白"又要"20 元预算"时，先算 `protein/price` 最高的单品给他看，
再说明"这价位蛋白能到 X g，再加 Y 元能到 Z g"，让他自己决定要不要加钱。**不要擅自突破预算。**

### 3.3 该问什么、不该问什么

| 该问 | 不该问 |
|---|---|
| 人数（赛题输入项） | 想喝什么饮料（看菜单有什么再说） |
| 预算上限（赛题输入项） | 要不要薯条（组合优化会决定） |
| **口味偏好**（赛题输入项） | 甜筒要不要（无关紧要） |
| **饮食偏好/忌口**（赛题输入项） | 具体要几分糖、去不去冰（核价时才需要） |
| 到店还是外送（决定查哪套门店库） | 品牌忠诚度、吃过哪几家 |

已经说过的不再问。追问上限 **2 轮**（每轮最多 4 题），超过就是在给用户做问卷。

**人数与预算的落点**：人数 → `--people N`；多人时 `--budget` 是**总额**（"100 块请 3 个人吃"就是 `--people 3 --budget 100`），热量/蛋白/钠约束是**人均**。卡片上总价写整单、旁边标人均。

**问法必须走 `AskUserQuestion`，单字段单题**，规则见 SKILL.md Gate 1。不要写字让用户回。


## 四、画像不是枷锁

画像只决定**排序指标**和**默认约束**，不决定推荐什么商品。
用户的临时要求（"我今天就想吃巨无霸"）永远压过画像。
