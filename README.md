# 麦乐配 · 麦当劳点餐搭配 Skill

告诉它几个人、多少钱、谁有忌口，它把菜单翻一遍、把套餐拆开、把热量和价格算准，
给你一张能直接照着点的配餐卡。**你点头，它才下单。**

适用于 WorkBuddy。数据全部来自麦当劳中国官方 MCP，
不预置静态菜单 —— 同城不同店同款汉堡存在差价，写死在文档里的价格必然是错的。

---

## 适合谁用

- 一个人吃饭，想控制热量，但不想逐条翻营养表
- 一群人聚餐，有人忌口、有人在减脂、预算还有上限
- 想比默认套餐点得更省，又懒得自己凑组合
- 不想为「今天吃什么」再花十分钟

---

## 它能替你做什么

**按人配，不是按人头乘。** 三个人吃饭、其中一位在减脂，它不会把三份一样的套餐摆上来。
那位吃 369 千卡的麦香鸡配纯悦，另外两位正常吃，再加一份大家分着吃的薯条 ——
每个人的热量各算各的，不会把一个人的控卡摊到全桌。

**套餐拆成单品。**「人气经典随心配」这种名字既不告诉人吃了什么，也没法逐项看热量。
它把套餐拆成一行一个商品，主食在前、饮品垫后，各自标千卡和份数。

**总价逐项核过。** 商品、运费、打包费分开列，实付金额来自官方算价接口，不是估算。
有优惠券也会算进去。

**一次问清，不挤牙膏。** 缺什么问什么，最多一轮四个问题。你已经说过的不会再问。

## 安装

**1. 放进技能目录**

```bash
git clone https://github.com/ilyc157/---skill.git ~/.workbuddy/skills/mcd-meal-planner
```

**2. 拿一个麦当劳 MCP token**

打开 <https://open.mcd.cn/mcp>，手机号登录 → 控制台 → 激活，免费。
接入地址是根路径 `https://mcp.mcd.cn`（加 `/mcp` 后缀会 404）。

**3. 把 token 配进去**，两种方式任选：

- 写进 `~/.workbuddy/mcp.json`，给麦当劳那个 server 加请求头
  `"Authorization": "Bearer <你的token>"`
- 或者设环境变量 `export MCD_TOKEN=<你的token>`

**4. 验证**

对 WorkBuddy 说：

> 帮我点麦当劳，一个人，预算 30 以内

能出卡片就是通了。报「找不到 token」就往回看第 3 步。

## 怎么用

不用记参数，把要求说成人话就行。

**一个人，控卡**

> 帮我点麦当劳，预算 35，热量别超过 700，要带饮料

**一群人，口味不一致**

> 我们三个人聚餐，有一个人不吃辣、在减肥，总预算 130

**外送到公司**

> 点麦当劳外送，送到科技园，两个人，80 块

它会先确认缺的信息（人数、预算、忌口、取餐方式、位置），然后直接给方案。
不满意可以说「换一批」，只改条件重算，不用重新报一遍需求。

---

## 你会看到什么

一张卡片，两套方案并排（窄屏上下排），每套包含：

- **具象的方案名** ——「双层吉士高蛋白套」，不是「方案 A」
- **逐行商品清单** —— 分类图标、菜名、份数、千卡；套餐已拆成单品
- **价格看板** —— 实付金额、立省多少、人均
- **营养看板** —— 合计热量、蛋白、钠，超限标红
- **三条依据** —— 为什么这样配，每条都指得回具体数字

多人且有人控卡时，清单会按「轻食 / 照常 / 共享」分组，每组标明这是几个人的、每人多少千卡。

---

## 它不会做的事

**没被明确选择，不下单。** 选项里出现「下单」两个字才算授权。
下单接口单账号每天有次数上限，取消订单不退还额度 —— 所以它不会拿真实订单做试验。

**查不到热量就写「未收录」。** 当季新品和部分甜品不在官方营养表里，
这种商品不参与控卡计算，卡片上标灰，不填 0，也不拿相似商品的热量凑数。

**不混用到店价和外送价。** 到店自取和麦乐送是两套菜单，同款可能差一块钱，
部分商品（比如随心配）只有到店有。取餐方式说错，价格就是错的。

---

## 已知限制

- **团餐阶梯优惠不在方案内。** 满 300、满 500 的折上折要在核价之后单独叠加。
- **门店库分三套**（到店自取 / 得来速 / 外送），门店编号不通用。
- **距离不是真实距离。** 查店返回的是关键词解析点到门店的直线距离，同一家店实测能差十几倍，
  所以它不会告诉你「离你多远」。
- **只做麦当劳。** 别的品牌不在范围内。
