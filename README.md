# 麦乐配 · 麦当劳点餐搭配 Skill

> 一个 WorkBuddy Skill：把「今天吃啥」从头做到尾 —— **问清楚 → 算明白 → 看着选 → 你点头才下单**。

菜单、价格、营养、优惠券全部来自麦当劳中国官方 MCP（`https://mcp.mcd.cn`，35 个工具）实时获取，不使用网页搜索，也不预置任何静态菜单 —— 同城不同店同款汉堡存在差价，预置价格必然算错。

---

## 一次完整流程要多久

v1.0 跑过一次完整流程用了 **十几分钟** —— 用户的评价是「人已经饿死了」。拆开看，慢的地方
一个都不在网络：

| 环节 | v1.0 | v1.1 | 怎么改的 |
|---|---|---|---|
| 拉数（门店+菜单+30 个套餐拆解+30 次核价+券） | 6.8s | 6.8s | 本来就是并发，没动 |
| 生成卡片 | **几分钟** | **<20ms** | 不再让模型逐字写 HTML，改 `render_card.py` 确定性渲染 |
| 读参考文档 | 60KB 五份全读 | 0 | 排障手册，正常流程不读 |
| 规划阶段调 MCP | 逐条调，一次菜单上千行 | 0 次 | 只跑脚本 |
| 追问 | 多轮挤牙膏 | 1 轮 4 题 | 一次问完 |
| 改条件重算（「换一批」） | 重拉全部 | **0.16s** | 只读调用加 5 分钟缓存 |

实测：冷启动规划+出卡 **8.5s**，热缓存重算 **0.16s**，脚本自报耗时（JSON 里的 `timing`）。

卡片交给脚本还顺带解决了三件事：品牌色不会跑偏、禁用词由代码拦截、
数字只能来自 planner 的 JSON（模型没有机会编）。

## 卡片长什么样（v1.2）

单卡 **≤432px**，`flex-wrap` 铺两列：宽屏两套并排横着比，窄屏（<860px）自动折成上下流式。
`--widget` 直接把片段塞进对话里的可视化工具，用户不用跳预览面板；该模式去投影、
基宽收到 300px（宿主容器约 680px，392 会被折成一列），属性统一单引号免转义。
**每单至少两套** —— 约束太紧时先松营养上限、再松预算补一套，补出来的带「超预算」角标。

五层动线（顺序固定）：

| 层 | 内容 | 关键约束 |
|---|---|---|
| L1 | 红底标题：`方案 A` + 角标 + **具象方案名** |「双层吉士」高蛋白暴击套 —— 不是「方案A」当标题 |
| L2 | 餐品清单：**套餐拆成单品**逐行，分类图标 + 「随心配-」来源前缀 + 单行菜名 + 份数 + 千卡胶囊 | 名字 `nowrap` 截断 + `title` 浮窗；查不到营养写「未收录」 |
| L3 | 价格看板：42px 实付 + 立省绿标 + 划线原价 + 人均 | 数字来自 `calculate-price`，运费打包另列 |
| L4 | 营养看板：合计 kcal / 蛋白 / 钠，超限自动标红 | 缺数据说「未收录」，不填 0 |
| L5 | 三条依据：算账 / 营养 / 口味或搭配 | 每条都指得回具体数字 |

餐品清单**不出现套餐 SKU 名**。「人气经典随心配」这种名字既不告诉人吃什么，也没法逐项看热量，
所以套餐和随心配一律按 `parts` 摊成单品，一行一个（主食在前、饮品垫后、甜品收尾），
同一单品跨套餐重复出现时合并份数。份数全清单一致时标题写「人手一份 ×3」，行内不再挂 ×3。
单品营养查不到就显示「未收录」的灰胶囊，不拿套餐合计摊到每行上。

**差异化配餐**（`--light-for N`）时清单分成三组，每组带一个小标题：

```
轻食  1 人            每人 369 kcal
  麦香鸡   369 kcal
  纯悦       0 kcal
照常  2 人            每人 614 kcal
  双层深海鳕鱼堡  485 kcal
  纯牛奶(盒装)    129 kcal
共享  大家分
  薯条  ≈289 kcal
```

底部营养看板也跟着改成「轻食那位 369 kcal」而不是「人均 629 kcal」——
控卡的人看到 629 会以为自己也吃了 629。

餐品图标不是官方产品图 —— 菜单接口给的是 427×320 促销横幅（带角标文案、撞色底），
缩到 34px 只剩色块，所以自绘 21 类 SVG（汉堡三种、薯条、薯饼、鸡块、炸鸡盒、芝士角、
玉米、苹果、圆筒、新地、麦旋风、派、冷饮、热饮、盒装奶、纯悦、蘸酱、套餐纸袋），
认不出类别时上红底金拱门。见 `scripts/mcd_icons.py`，`python3 scripts/mcd_icons.py out.html`
可导出全部图标的 34/56/96 对照表。

设计令牌写死在 `render_card.py` 顶部，不跟随宿主主题：红 `#DA291C`、金 `#FFBC0D`、
奶油 `#FFF8E7`、炭黑 `#27251F`、中灰 `#8C857B`、省钱绿 `#1B873F`；外层圆角 18px、内层 12px。

三个兜底都在代码里，不靠自觉：

1. **图挂了** → `onerror` 换成红底金字金拱门 SVG 徽章，商品无图时直接画徽章，不留白块。
2. **长菜名** → 单行截断 + `title`，撑不破行。
3. **窄屏** → 卡片 `min-width:0`（flex 子项默认 `auto` 会把卡顶出屏幕），375px 下无横向溢出。

## 赛题对齐

| 赛题输入 | 落点 |
|---|---|
| **人数** | Gate 1 必问 → `--people N`。多人时预算是总额、营养约束是人均 |
| **预算** | Gate 1 必问 → `--budget`。到店价与外卖价是两套菜单，运费打包另计 |
| **口味与饮食偏好** | Gate 1 必问 → 口味映射 `--include/--exclude`，饮食偏好映射 `--kcal-max/--protein-min/--sodium-max/--objective` |

| 赛题要求 | 硬性做法 |
|---|---|
| **搭配清晰** | 逐件分行，主品/配品分层，份数写明；套餐必须展示拆解子项 |
| **总价有依据** | 逐项构成：商品 ＋ 运费 ＋ 打包 ＝ 实付，不许只给一个数 |
| **选择有依据** | 每套方案有一句排序理由，三条依据各自指得回具体商品或具体约束 |

## 为什么不是「随机推个套餐」

三个数字说明它到底做了什么：

**1. 套餐必须拆。** 菜单里的套餐在营养表里没有条目。直接按名字查，只命中 **16.5%（18/109）**；调 `query-meal-detail` 把套餐拆成子项再累加，命中率到 **87.2%（34/39）**。不拆就是拿「麦香鱼」的 325 kcal 去冒充「麦香鱼套餐」的 761 kcal。

**2. 营养缺失不能当 0。** 缺数据的商品如果填 0 参与控卡计算，方案会看着合规、实际超标。求解器把这类商品直接排除，并在卡片上标「未收录」。

**3. 外送和到店是两套菜单。** 同一家店同一晚：到店 122 个 SKU 有「随心配」，外送 125 个 SKU 一个都没有，同款还贵 1 元。算价接口报 `60006 商品已售罄`，真实含义是「这份菜单不属于这个 orderType」。

配套的还有四重约束（热量／蛋白／钠／预算）、营养指纹去重（防止多买 0 卡饮料凑单）、以及 `calculate-price` 真实核价（返回单位是**分**，不是元）。

## 三道门

```
Gate 1 追问（AskUserQuestion，一次 ≤4 题，1 轮）
   ↓
Step 2 一条命令：门店 → 菜单 → 拆套餐 → 求解 → 核价 → 出卡（8.5s）
   ↓
Gate 2 展示 + 选择：present_files 打开卡片 → 用户选哪套
   ↓
Gate 3 下单：用户选定后才调 create-order
```

设计上有两条不可让的规矩：

- **所有需要用户输入的地方一律走 `AskUserQuestion`**，不在正文里写「请告诉我你的地址」让用户打字。单字段单题，题目里写清填写格式，选项位只放真实分支决策 —— 放「送到门牌／送到门口」这类伪装成答案的选项，用户选了照样拿不到地址。
- **没被明确选择，不下单。** 选项文字里必须出现「下单」两个字，且 `create-order` 全流程只调一次 —— 麦当劳 MCP 单账号每日下单有硬上限（约 4 次），取消订单**不退还**额度。

## 使用

### 作为 WorkBuddy Skill

把整个目录放进 `~/.workbuddy/skills/`，然后直接说需求：

> 帮我点麦当劳，1 个人，预算 30 以内，想吃辣，热量别超过 700

### 命令行

```bash
# 一条命令出方案 + 卡片（--widget 给对话内嵌，--html 给独立页面）
python3 scripts/mcd_planner.py --city 雄安 --keyword 容东 --people 3 --budget 60 \
    --meal 晚餐 --widget /tmp/mcd_plan.html --brief

# 控卡单人餐
python3 scripts/mcd_planner.py --city 雄安 --keyword 容东 --people 1 \
    --kcal-max 700 --protein-min 25 --budget 35 --structure with_drink --html /tmp/mcd_plan.html

# 已知 storeCode
python3 scripts/mcd_planner.py --store 1950739 --budget 30

# 多人：3 人总预算 90，人手一份 / 分享装 / 差异化三条路并跑
python3 scripts/mcd_planner.py --store 1950739 --people 3 --budget 90

# 3 人聚餐、其中一位在减肥：700 是那一人的上限，其余两位按常规量
python3 scripts/mcd_planner.py --store 1950739 --people 3 --budget 130 \
    --meal 午餐 --kcal-max 700 --light-for 1 --exclude 辣

# 外送：order-type=2 时 be-type 也是 2，且必须带 beCode
python3 scripts/mcd_planner.py --store 1950401 --be-type 2 --order-type 2 \
    --be-code 195040102 --budget 20
```

输出一份 JSON（门店、约束、每套方案的商品／价格／营养／核价），`--html` 额外产出一张品牌卡片。`--meal` 必传：菜单按时段切，不传会把早餐菜单当晚餐算。

**选完方案后的二次渲染**：`--html` / `--widget` 会在卡片旁落一份 `.json` 存档。
用户挑定某一套时用 `--from --pick`，只换渲染、不重算 —— 实测 **8.76s → 0.02s**。

```bash
python3 scripts/mcd_planner.py --store 1950401 --people 3 --budget 130 \
    --meal 午餐 --kcal-max 420 --light-for 1 --top-k 2 --html /tmp/plan.html

# 用户说「要第二套」
python3 scripts/mcd_planner.py --from /tmp/plan.html.json --pick 2 --html /tmp/plan_b.html
```

### 配置

MCP 优先。工具名带 `mcp__mcdonald__` 前缀时直接调用；没挂载时脚本回落到同一端点，用同一个 token：

1. `MCD_TOKEN` 环境变量
2. `~/.workbuddy/mcp.json` → 名字含 `mcd` 的 server 的 `Authorization` 头

Token 去 <https://open.mcd.cn/mcp> 手机号登录 → 控制台 → 激活，免费获取。接入地址是根路径 `https://mcp.mcd.cn`，加 `/mcp` 后缀返回 404。

## 已知边界

- **`create-order` 未做真实订单验证** —— 会真实扣款，不能拿来试。参数骨架按工具 schema 写，`takeWayCode` 取自 `calculate-price` 返回的 `takeWayList[].code`。
- **团餐阶梯优惠不在求解器内。** `query-meal-assistance` 的满 300/500 阶梯折上折要在核价后单独叠加，不能和商品价混着报。
- **营养表覆盖不全。** 当季新品、部分甜品未收录，遇到就标「未收录」，不拿相似商品凑数。
- **门店库分三套**（到店自取 / 得来速 / 外送），`storeCode` 不通用。
- **`distance` 不是真实距离** —— 它是关键词解析点到门店的直线距离，实测同一家店能差 13 倍，不能说成「离你多远」。
